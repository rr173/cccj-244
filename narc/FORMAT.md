# narc 归档线格式（v1）

narc 是为仪器归档设计的**定长、大端、自描述**容器。格式不依赖任何通用压缩
库；所有多字节整数均为大端，记录长度固定，便于用 `pread` 做窄窗随机读取。

## 1. 顶层布局

```
文件头 (12B) | 片段头/块头/块负载 重复 | 归档结束标记 (2B)
```

### 文件头（12 字节）

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 8 | 魔数 `INARCV01` |
| 8 | 2 | 字节序标记，固定 `0xFEFF`（大端）；`0xFFFE` 视为外来字节序拒绝 |
| 10 | 2 | 格式版本，当前为 `1` |

### 结构标签（1 字节）

| 标签 | 值 | 含义 |
|---|---:|---|
| `F` | 0x46 | 片段头 |
| `B` | 0x42 | 块头 |
| `E` | 0x45 | 归档结束标记，后随 1 字节保留标志（必须为 0） |

## 2. 片段头（28 字节）

| 字段 | 宽度 | 说明 |
|---|---:|---|
| 标签 `F` | 1B | 固定 0x46 |
| 标志 | 1B | 保留，必须为 0 |
| 片段 ID | 2B | 归档内唯一 |
| 源文件名 | 16B | UTF-8，NUL 填充 |
| 起始样点 | 4B | 全局样点坐标（含） |
| 结束样点 | 4B | 全局样点坐标（不含，半开区间） |

片段声明其身份、来源与样点半开范围 `[start_row, end_row)`。

## 3. 块头（60 字节）与块负载

| 字段 | 宽度 | 说明 |
|---|---:|---|
| 标签 `B` | 1B | 固定 0x42 |
| 块种类 | 1B | `1` 独立块 / `2` 依赖块 |
| 列 ID | 2B | 片段内的列编号 |
| 记录数 | 4B | 等于行范围长度 |
| 起始行 | 4B | 含 |
| 结束行 | 4B | 不含 |
| 负载偏移 | 4B | 必须紧跟块头 |
| 负载长度 | 4B | 字节数 |
| 负载摘要 | 32B | 负载的 SHA-256 |
| 保留字段 | 4B | 必须为 0 |

**同一片段同一列的块行范围不得重叠；依赖块必须与紧邻前块行连续。**

### 记录（固定 9 字节）

每条记录 = 1 字节标签 + 8 字节带符号 64 位整数（大端 `int64`）。

| 记录标签 | 值 | 8 字节负载 | 语义 |
|---|---:|---|---|
| 缺测 | 0 | 必须全 0 | 显式缺测，**不改变**上一有效值 |
| 绝对值 | 1 | int64 | 重建值直接等于该值 |
| 增量 | 2 | int64 | 重建值 = 可信前值 + 该增量 |

解码后用宿主语言整数运算重建，**不再施加 64 位界值限制**；只有记录负载本身
必须落在带符号 int64 范围内。

### 块种类与重启语义

- **独立块（kind=1）**：可独立重启。首个绝对值之前出现的增量非法，查询时
  返回 `missing_prefix`；块内绝对值会使其后的值不再依赖块外状态。
- **依赖块（kind=2）**：依赖同片段同列紧邻前块。若无可信前值（无前块、前块
  损坏、前块无任何可信绝对值），其增量无法解出，返回 `missing_prefix`；块内
  一旦出现绝对值，后缀立即恢复可读。

## 4. 不可读块与隔离规则

以下任一情况使**整个块不可读**，编目标记 `damaged`：

1. 截断：声明负载超出文件实际长度，或长度与记录数不符；
2. 摘要不符：负载 SHA-256 与块头声明不一致；
3. 含非法行：未知记录标签，或缺测记录携带非零负载。

下游块**不能跨过坏前缀借用更早的值**；但若下游块内部出现可信绝对值，该绝对
值之后的后缀仍可读。损坏块在查询时逐行返回 `damaged`，且不产生任何负载字节
读取。

## 5. 编目（JSON 侧车）

编目是独立于源文件的 JSON 文件，包含：

- 不可变来源身份：源文件绝对路径、字节大小、整文件 SHA-256；
- 片段身份、源文件名、样点半开范围；
- 每列每个块的块标识、种类、行范围、负载字节范围、负载摘要、可读/损坏状态；
- 重建摘要：首个绝对值位置、入口可信值 `carry_in`、块末重建值、稀疏检查点、
  首个绝对值之前的显式缺测位置。

编目允许读全量，但**不保存完整解码影本**。来源身份不可变：大小变化在每次
查询时直接拒绝；内容变化由完整 SHA-256 校验捕获。更换来源版本必须重新编目。

### 稀疏检查点

每个块在所有绝对值位置、以及块内相对位置为 256 倍数处保存当时的精确重建值。
窄窗查询从“不晚于窗口首行的最近检查点”开始读，读取量上界约为
`256 + 窗口宽度` 条记录，绝不从文件头或列首顺扫。

## 6. 查询读取边界

查询 `[start_row, end_row) × columns` 时：

1. 只用编目元数据定位与窗口相交的块，不解析源文件结构；
2. 打开文件时把可读范围限制为这些块的**负载区间**并集，任何越界读取直接抛错；
3. 每个物理读区间、字节数都记入读取台账并随结果返回；
4. 不请求的列、不相交的块、损坏块的负载一律零字节读取。

每个返回单元携带：行号、列号、状态（`value` / `missing` / `damaged` /
`missing_prefix` / `uncovered`）、精确值（若有）、所用块标识。

## 7. 离线发布交付（release）

`release` 不引入新的线格式：每个分件都是本格式定义的标准 v1 文件，接收端用
既有的 `catalog` / `query` 即可单独打开。交付目录的额外约定只有一个
`parts.json` 清单。

### 分件（v1 文件）

- 文件头、片段头、块头、记录与结束标记完全沿用第 1–3 节；
- 一个分件只有一个片段头，片段 ID 等于授权单的 `fragment_id`，片段来源名固定
  为 16 字节内的 UTF-8 字符串 `release`（原来源名不出现在任何分件中）；
- 分件内每个块都是**独立块（kind=1）**，且块内第一条值记录必为绝对值，其
  负载是该位置的精确重建值。因此分件无需任何其它分件或原档前值即可解码；
- 块只覆盖获准列的获准且有覆盖的样点；无覆盖位置不产生任何块行，查询时仍按
  第 6 节返回 `uncovered`，不会被写成显式缺测；
- 分件总字节（含文件头、片段头、全部块头与负载、结束标记）不得超过授权单的
  `max_bytes`；
- 重建值仍按宿主语言任意精度运算；只有绝对值锚的负载必须落在带符号 int64
  范围内，超限的精确值继续以增量链表达，不截断、不虚构锚点。

### `parts.json`

```json
{
  "parts": [
    {
      "file": "part-00001.narc",
      "start_row": 0,
      "end_row": 12,
      "bytes": 198,
      "sha256": "…"
    }
  ]
}
```

- `parts` 按样点顺序排列；每件给出文件名、半开区间 `[start_row,end_row)`、
  实际字节数和整文件 SHA-256（小写十六进制）；
- 各件区间互不重叠；同属一个授权区间的分件首尾相接，且没有任何分件跨越两个
  授权区间之间的空档；全部区间的并集恰好是授权区间（重叠/相邻的授权区间在
  校验时已合并）。

### 失败原子性

发布先在交付目录的父目录下使用隐藏临时目录写入，全部部分和清单落盘并核对后
才整体重命名为目标目录；任何无解、输入无效或写入失败都不会创建最终交付目录，
接收端不可能观察到部分分件。
